# Project Context Rules

## Product

- Build for Cuoc24h: a web MVP for independent taxi/service drivers and customers.
- Treat the current MVP as a dispatch-support system, not a full ride-hailing platform.
- Keep customer booking public and frictionless.
- Keep driver registration separate from customer booking.
- Keep admin workflows practical for manual dispatch.

## Core Documents

Read these before major changes:

- `docs/00-index.md`
- `docs/01-project-overview.md`
- `docs/02-product-requirements.md`

## MVP Boundaries

Do not implement these unless explicitly requested:

- Customer accounts
- Online payment
- Realtime driver tracking
- Automatic driver matching
- In-app chat
- Native mobile app

## Domain Language

Use these terms consistently:

- Booking: customer ride request.
- Driver: service taxi driver registering to join the platform.
- Admin: dispatcher/operator managing bookings and drivers.
- Zalo notification: message sent to the dispatch group.
