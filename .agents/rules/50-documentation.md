# Documentation Rules

## When To Update Docs

Update docs when changing:

- MVP scope
- User flows
- API contracts
- Database schema
- Authentication behavior
- Notification behavior
- Deployment or environment setup

## Where To Document

- Product scope: `docs/01-project-overview.md`
- Requirements: `docs/02-product-requirements.md`
- User flows: `docs/03-user-flows.md`
- Architecture: `docs/04-system-architecture.md`
- Database: `docs/05-database-design.md`
- API: `docs/06-api-spec.md`
- UI/UX: `docs/07-ui-ux-guidelines.md`
- Zalo: `docs/08-zalo-notification.md`
- Admin and driver workflows: `docs/09-admin-driver-management.md`
- Roadmap: `docs/10-development-roadmap.md`

## Style

- Use concise Markdown.
- Prefer concrete examples over vague notes.
- Keep docs aligned with implementation.
- Mark assumptions clearly when decisions are not final.
